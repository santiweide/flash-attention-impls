\section{Problem Statement}

Flash Attention proposed by Dao-AILab is an IO-aware exact attention algorithm that uses tiling to reduce the number of memory reads/writes between GPU high bandwidth memory (HBM) and GPU on-chip SRAM\cite{dao2022flashattention} \cite{dao2023flashattention}. In this report, we implement Flash Attention(FA) forward pass with different Domain Specific Languages(DSLs): CUDA, CUDA+Cutlass, PyTorch and PyTorch + Triton.

\subsection{What is Attention and what does Flash Attention do}
The calculation process of Attention is as follows:

\[
S = QK^{T} \quad P = \text{Softmax}(S) \quad O = PV
\]

Among them, the Q, K, and V matrices are generated from the input sequence, while S and P are intermediate matrices, and O is the resulting matrix after the Attention computation.

FlashAttention leverages shared memory to reduce accesses to high-bandwidth memory (HBM). It applies tiling to the $Q$, $K$, and $V$ matrices and modifies the softmax computation to operate efficiently on local tile-level results. In FlashAttention v1, the $Q$ matrix is loaded as a whole while $K$ and $V$ are split  during matrix multiplication (split-$K/V$). See Algorithm~\ref{alg:flashattention1}. In FlashAttention v2, $Q$ is instead split across threads or warps (split-$Q$), while $K$ and $V$ remain fixed. See Algorithm~\ref{alg:flashattention2}.

\begin{algorithm}[htbp]
\caption{FlashAttention-1 (Split-K, Parallel over Warps)}
\label{alg:flashattention1}
\begin{algorithmic}[1]
\FOR{each block of keys/values $K_j, V_j$}
    \STATE \textbf{in parallel over warps $w$:} \COMMENT{Each warp processes a $Q_i$ tile}
    \STATE \hspace{0.5cm} $S_{\text{local}} = Q_i K_j^{T}$ \COMMENT{partial attention scores}
    \STATE \hspace{0.5cm} $P_{\text{local}} = \text{softmax\_tile}(S_{\text{local}})$ \COMMENT{local normalization (approx.)}
    \STATE \hspace{0.5cm} $O_{\text{partial}} = P_{\text{local}} V_j$ \COMMENT{partial output}
    \STATE \textbf{synchronize and sum across warps} \COMMENT{combine all $O_{\text{partial}}$}
    \STATE \textbf{update running normalization stats} \COMMENT{for true softmax}
\ENDFOR
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[htbp]
\caption{FlashAttention-2 (Split-Q, Fully Parallel Warps)}
\label{alg:flashattention2}
\begin{algorithmic}[1]
\STATE \textbf{in parallel over warps $w$:} \COMMENT{Each warp handles its own $Q_i$ tile}
\STATE \hspace{0.5cm} initialize $O_w = 0$, normalization stats
\STATE \hspace{0.5cm} \textbf{for} each $K_j, V_j$ block \textbf{do}
\STATE \hspace{1.0cm} $S_{\text{local}} = Q_w K_j^{T}$
\STATE \hspace{1.0cm} $P_{\text{local}} = \text{softmax\_tile}(S_{\text{local}})$
\STATE \hspace{1.0cm} $O_w \mathrel{+}= P_{\text{local}} V_j$ \COMMENT{accumulate output locally}
\STATE \hspace{0.5cm} \textbf{end for}
\STATE \hspace{0.5cm} finalize normalization
\STATE \hspace{0.5cm} write $O_w$ to global output
\end{algorithmic}
\end{algorithm}
\subsection{Work-Depth Complexity}

Here we count only matrix multiplication for FLOPs calculation, since $Softmax$ involves much fewer FLOPs. For a matrix $A$ of size $m \times n$ and a matrix $B$ of size $n \times p$,  the multiplication $A \times B$ requires $m \times n \times p$ multiplications and $m \times n \times p$ additions, totaling $2mnp$ FLOPs.

Let $N$ be the sequence length, $b$ be the batch size, $h$ be the head number and $d$ be the head dimension.

\textbf{Work Complexity: } The work complexity is unified with Attention\footnote{Note that we ignore the $Q=xW_Q$, $K=xW_K$, $V=xW_V$, $O=xW_O$ since we did not implement that in code. This is aligned with in original flash attention 2 paper on page 10.}.


\textbf{Score ($S = QK^T$):} This computes the $N \times N$ score matrix.

Size: $(b, h, N, d) \times (b, h, d, N) \rightarrow (b, h, N, N)$

FLOPS: $2 \cdot b \cdot h \cdot N \cdot d \cdot N = 2 \cdot b \cdot (h \cdot d) \cdot N^2$

\textbf{Output ($O = PV$):} This computes the $N \times d$ output matrix.

Size: $(b, h, N, N) \times (b, h, N, d) \rightarrow (b, h, N, d)$

FLOPS: $2 \cdot b \cdot h \cdot N \cdot N \cdot d = 2 \cdot b \cdot (h \cdot d) \cdot N^2$

$$ Total\, FLOPS = (2 \cdot b \cdot d \cdot N^2) + (2 \cdot b \cdot d \cdot N^2) = 4 \cdot b \cdot d \cdot N^2 $$


\textbf{Depth Complexity: } Different tiling strategy brings different depth complexity. See each one's session for more details.


\subsection{Evaluation Metrics}
We focus on latency speedup, compute efficiency, and memory efficiency.\footnote{We intended to measure the achieved memory bandwidth, but were unable to install \textit{Nsight Compute} successfully.} Latency speedup is assessed using kernel runtime of the execution time $(T)$ of the self-attention forward. Here our baseline is a naive Attention implementation with no shared memory or warp-level optimizations ($\text{Speedup} = \frac{T_{\text{Base}}}{T_{\text{FlashAttention}}}$).

For compute efficiency we use achieved Tera Floating-Point Operations Per Second(TFLOPs/s): 

$$\text{Achieved TFLOPs/s} = \frac{\text{Total Floating-Point operations in FA}}{T_{\text{Execution Time}}}$$.

We compare the achieved TFLOPs/s with the state-of-art TFLOPS in FA papers to see if we are using the GPU compute resource efficiently. The achieved TFLOPs/s of FA1 in paper is 25-40\% of the theoretical matmul TFLOPs/s with FP16/BF16 on A100. And for FA2 is 50\%-73\% of that\cite{dao2023flashattention}. Specifically, when head dimension is 128, FA2 can achieve 225 TFLOPs/s in forward pass.

\section{CUDA by Zhigao Yan}

\subsection{Implementation}
I implemented a CUDA FlashAttention kernel that uses FP16 for inputs/outputs, performs all computations and accumulation in FP32, and casts back to FP16 only once at the end for numerical stability. The pipeline is: preload the current $Q$ tile into shared memory for reuse, then load $K/V$ tiles into shared memory; for each $K/V$ tile, maintain per-row running max $m$ and normalizer $l$ for numerically stable online softmax merging. Accumulate outputs in FP32 across tiles, then perform final normalization by $l$ and write back in FP16.
\begin{lstlisting}
    // preload Q tile into shared memory (reuse across KV tiles)
    for (int t = threadIdx.x; t < br_size * d; t += blockDim.x) {
        int r = t / d;
        int c = t % d;
        Qi[r*d + c] = Q_bh[(qi_start + r)*d + c];
    }
    ...
        // load current K/V tile into shared memory
        for (int t = threadIdx.x; t < bc_size * d; t += blockDim.x) {
            int r = t / d, c = t % d;
            Kj[r*d + c] = K_bh[(kj_start + r)*d + c];
            Vj[r*d + c] = V_bh[(kj_start + r)*d + c];
        }
        ...
            // stable online merge: update running max
            float m_new = fmaxf(m_row, m_til);

            // compute correction factors and new normalizer
            float a = expf(m_row - m_new);
            float b = expf(m_til - m_new);
            float l_new = a * l_row + b * l_til;

            // update O_accum: apply correction then add new contribution
            float correction = a;  
            for (int col = 0; col < d; ++col) {
                O_accum[r * d + col] *= correction;
                float acc = 0.0f;
                for (int c = 0; c < bc_size; ++c) {
                    acc += P_til[c] * __half2float(Vj[c*d + col]);
                }
                O_accum[r * d + col] += b * acc;
            }
\end{lstlisting}

\section{CUTLASS-based FlashAttention Implementation by fng685}

\subsection{Implementation}

This implementation leverages NVIDIA CUTLASS with WMMA (Warp-Matrix-Multiply-Accumulate) tensor core instructions for accelerated matrix operations in Flash Attention. For convenience we extract head dim as template variable to match different tiling size for shared memory allocation.

\paragraph{Tensor Core Acceleration}
The $S = Q K^{\top}$ (attention scores) computation is accelerated using WMMA tensor cores with \texttt{fp16} inputs and \texttt{fp32} accumulation, employing tile dimensions of $16 \times 16 \times 16$ to match the A100 instruction format. Since the lay out handles tiles with the fixed size, there will be some remaining elements to be calculate, and they are calculated with CUDA cores then. The result is accumulated into shared memory.


\begin{lstlisting}     
     if (q_size >= WMMA_M && k_size >= WMMA_N && DIM_K >= WMMA_K) {
         //   Q is [M, K] row-major
         //   K is [N, K] row-major, need to treat as K^T [K, N]
         for (int m = warpId * WMMA_M; m < (q_size / WMMA_M) * WMMA_M; m += numWarps * WMMA_M) {
             for (int n = 0; n < (k_size / WMMA_N) * WMMA_N; n += WMMA_N) {
                 wmma::fragment<wmma::matrix_a, WMMA_M, WMMA_N, WMMA_K, half, wmma::row_major> a_frag;
                 wmma::fragment<wmma::matrix_b, WMMA_M, WMMA_N, WMMA_K, half, wmma::col_major> b_frag;  // K^T is col-major!
                 wmma::fragment<wmma::accumulator, WMMA_M, WMMA_N, WMMA_K, float> c_frag;
                 
                 wmma::fill_fragment(c_frag, 0.0f);
                 
                 // Multiply-accumulate over K dimension
                 for (int k = 0; k < (DIM_K / WMMA_K) * WMMA_K; k += WMMA_K) {
                     // Load A (Q[m:m+16, k:k+16]) - row major
                     wmma::load_matrix_sync(a_frag, reinterpret_cast<const half*>(Q + m * DIM_K + k), DIM_K);
                     
                     // Load B (K^T[k:k+16, n:n+16]) = K[n:n+16, k:k+16] as col-major
                     // K is stored row-major as [N, K], so K[n, k] is at K + n*DIM_K + k
                     wmma::load_matrix_sync(b_frag, reinterpret_cast<const half*>(K + n * DIM_K + k), DIM_K);
                     
                     // C = A @ B^T + C
                     wmma::mma_sync(c_frag, a_frag, b_frag, c_frag);
                 }
                 
                 wmma::store_matrix_sync(S + m * TILE_N + n, c_frag, TILE_N, wmma::mem_row_major);
             }
         }
         
         __syncthreads();
     }
     
     // Handle remainder with standard CUDA cores
     // This handles: partial tiles, edge cases, and any K dimension remainder
     for (int idx = tid; idx < q_size * k_size; idx += num_threads) {
         int i = idx / k_size;
         int j = idx % k_size;
         
         // Skip if already computed by WMMA
         if (q_size >= WMMA_M && k_size >= WMMA_N && DIM_K >= WMMA_K) {
             int m_base = (i / WMMA_M) * WMMA_M;
             int n_base = (j / WMMA_N) * WMMA_N;
             if (i >= m_base && i < m_base + WMMA_M && 
                 j >= n_base && j < n_base + WMMA_N && 
                 m_base < (q_size / WMMA_M) * WMMA_M && 
                 n_base < (k_size / WMMA_N) * WMMA_N) {
                 continue;  // Already computed by tensor cores
             }
         }
         
         float sum = 0.0f;
         #pragma unroll
         for (int k = 0; k < DIM_K; k++) {
             sum += float(Q[i * DIM_K + k]) * float(K[j * DIM_K + k]);
         }
         S[i * TILE_N + j] = sum;
     }
     __syncthreads();
 }
\end{lstlisting}


For the $O = P V$ (output projection) computation, CUDA cores are utilized instead of tensor cores. This design choice stems from the fact that attention probabilities $P$ are maintained in \texttt{fp32} precision for numerical stability during online softmax updates, while WMMA requires \texttt{fp16} inputs. Converting $P$ from \texttt{fp32} to \texttt{fp16} would incur additional overhead that outweighs the performance benefits, since the $P \times V$ computation is less compute-intensive than $Q \times K^{\top}$ (P shaped $TILE\_M \times TILE\_N$, V shaped $TILE\_N \times HEAD\_DIM$, and Q shaped $TILE\_M \times HEAD\_DIM$, K shaped $TILE\_N \times HEAD\_DIM$).


\paragraph{Softmax Computation}
The softmax operation is parallelized at the warp level using cooperative warp shuffle operations (\texttt{\_\_shfl\_down\_sync}, \texttt{\_\_shfl\_sync}). This implements an online softmax algorithm with Welford-style running statistics correction. Each warp processes one or more query positions cooperatively: threads within a warp collectively compute the maximum across the sequence dimension, apply exponential scaling, and reduce the normalization factor $l$. The online softmax update rule applies a correction factor $e^{m_{\text{old}} - m_{\text{new}}}$ to previously accumulated outputs, enabling sequential processing of key-value tiles without storing the full attention matrix.

\paragraph{Precision and Accumulation}
All input tensors ($Q$, $K$, $V$) are maintained in \texttt{fp16} format. Intermediate computations employ \texttt{fp32} accumulators for attention scores ($S$), attention probabilities ($P$), and output accumulation ($O_{\text{accum}}$), ensuring numerical precision is preserved throughout the iterative online softmax process.

\subsection{Validation}

\paragraph{Correctness:} The kernel's output was validated against a naive CUDA implementation using identical inputs, demonstrating a relative error of less than 2\%. This minor deviation is expected due to the use of \texttt{fp16} for data representation and intermediate calculations, which introduces accumulation errors. Warmup is introduced for initializing cache memory and create CUDA context, so that these one-way cost will not influence the latency and throughput.

\paragraph{Dataset:} Test cases were generated using randomly shaped tensors (weights and inputs) populated with random \texttt{fp16} values to prevent overflow. The shapes varied in sequence length ($N$), head number ($H$), and head dimension ($D$) to benchmark performance and approach the maximum TFLOPs/s. Based on the evaluation tables, all test cases use a fixed batch size of 1.

\paragraph{Parameter Choice:} An additional key parameter in the FlashAttention algorithm is the tile size. In addition to the naive baseline, a non-CUTLASS FlashAttention was first implemented with two different tile sizes ($45 \times 90$ and $120 \times 120$) to identify a suitable configuration. These tile sizes were selected to fit within the 192KB shared memory limit per Streaming Multiprocessor (SM) of the A100-40G GPU \cite{nvidia2022a100}. The memory footprint for a given tile is calculated as shown in Section~\ref{sec:mem-acc}.

\subsection{Depth Complexity}
% This section has been rewritten, as the original analysis incorrectly equated
% work complexity (O(N^2)) with parallel depth complexity.

The parallel depth of an algorithm represents the longest chain of dependent operations. Let $T_r = N / B_r$ and $T_c = N / B_c$ be the number of query and key/value blocks, respectively, where $B_r$ and $B_c$ are the tile dimensions.

The FlashAttention algorithm parallelizes the outer loop over $T_r$ (the query blocks) by assigning each block to a separate CUDA thread block. These blocks execute in parallel.

Within each thread block (processing one $Q$ tile), the algorithm must iterate \textit{sequentially} through all $T_c$ blocks of $K$ and $V$. The computation within this inner loop (a tile-matrix multiply and the warp-reduce softmax) has a near-constant depth $D_{\text{inner}}$, or $O(\log B_c)$ for the reduction.

The total parallel depth is therefore dominated by the sequential inner loop, as all outer loop blocks run in parallel.
\[
D_{\text{FA1}} = O(T_c \times D_{\text{inner}}) \approx O(T_c) = O(N / B_c) \approx O(N).
\]
This $O(N)$ depth is a fundamental improvement over the $O(N^2)$ \textit{work} complexity, which the naive implementation also suffers from in terms of depth due to its large matrix materialization.

\subsection{Shared Memory Access}
\label{sec:mem-acc}

Shared memory is used to store the tiles of $Q$, $K$, and $V$, as well as the intermediate results for $S$, $P$, and the output accumulator $O$. It also stores the online softmax statistics (the row-wise maximum $m$ and sum of exponentials $l$).
\begin{lstlisting}
static constexpr size_t get_smem_size() {
    return (kTileM * kHeadDim + kTileN * kHeadDim * 2) * sizeof(cutlass::half_t) +
           (kTileM * kTileN * 2) * sizeof(float) +  // S and P
           (kTileM * 2) * sizeof(float) +          // m, row-wise max; l, row-wise sum of exponentials
           (kTileM * kHeadDim) * sizeof(float);   // O_accum
}
\end{lstlisting}

\subsection{Evaluation and Results}
The evaluation was conducted on an A100-40G GPU, tested on CUDA 12.8 with CUTLASS 3.4.0. The CUDA driver version was $545.23.08$.

The naive implementation relies entirely on HBM and does not utilize shared memory. Consequently, it is memory-bound, with the GPU spending most of its time stalled on HBM accesses rather than performing computation. In contrast, the tiled versions demonstrate significantly lower latency by leveraging shared memory.

The CUTLASS-based implementation (using a $45 \times 90$ tile) achieves the best latency across all test cases. This is attributed to its use of CUTLASS WMMA, which maps operations efficiently to the A100's Tensor Cores using a $16 \times 16 \times 16$ tile layout for Threadblock shape and Warp shape, and $16 \times 16 \times 16$ for instruction shape.

See throughput result in Table~\ref{tab:throughput_comparison} and latency result in Table~\ref{tab:full_comparison}. The speed up rate of Cutlass implementation against Naive implementation indicates Flash Attention is memory bounded\footnote{However, it is quite hard to give a quantitative analysis of speedup without the help of Nsight Compute.}. Another interesting discovery is that the large tile fully utilizing shared memory is not performing as well as small tile. For large tile, the single tile will do more FLOPS, but the concurrency across tiles will be limited.

\section{PyTorch by Yuxuan Chen}
\subsection{Implementation}

This report documents a reproducible microbenchmark that compares \textbf{FlashAttention-2 (FA2)}\footnote{Invoked via \texttt{flash\_attn\_qkvpacked\_func} if available.} against \textbf{PyTorch Scaled Dot-Product Attention (SDPA)}. The harness measures latency, tokens/s throughput, and peak CUDA memory under controlled shapes and dtypes, and can also search the maximum stable batch size before out-of-memory (OOM).

\paragraph{Interfaces and Tensor Layouts}
\begin{itemize}
\item \textbf{FA2 path:} expects a single packed tensor $qkv \in \mathbb{R}^{B \times S \times 3 \times H \times D}$ and returns the attention output in the same packed convention.
\item \textbf{SDPA path:} requires separate $q, k, v \in \mathbb{R}^{B \times H \times S \times D}$. We therefore permute from $[B,S,H,D] \rightarrow [B,H,S,D]$ and call \texttt{contiguous()} to ensure compact layout, which introduces an extra materialization cost relative to FA2’s packed path.
\end{itemize}

\paragraph{AMP and Precision}
We default to \textbf{BF16} autocast (\texttt{torch.cuda.amp.autocast(enabled=True, dtype=\{bf16|fp16\})}). BF16 is typically more numerically stable than FP16 while still activating tensor cores on modern GPUs. All reductions and the \texttt{total\_sum\_guard} checksum are computed in FP32 to avoid cancellation or overflow.

\paragraph{Warmup, Timing, and Guard Value}
We separate warmup ($W$ iters) from measurement ($T$ iters). The \emph{Guard value (sum)} is a checksum of the output tensor in FP32 ($\sum O$) to prevent dead-code elimination and to expose silent NaN/INF regressions across runs. Small drift across runs is expected with low-precision math, but large deviations indicate numerical or correctness issues.

\paragraph{Batch Search for Capacity}
The utility \texttt{find\_max\_batch} doubles $B$ until an OOM or CUDA error occurs, returning the last stable $B$ for the requested $(H,S,D)$ and backend. This maps memory ceilings for different shapes and dtypes.

\subsection{Validation}

\paragraph{Rationale}
We validate functional equivalence by cross-checking FA2 vs.\ SDPA outputs under identical random seeds and shapes:
\[
\text{max\_abs\_diff} = \max |O_{\text{FA2}} - O_{\text{SDPA}}|, \qquad
\text{rel\_err} = \frac{\|O_{\text{FA2}} - O_{\text{SDPA}}\|_2}{\|O_{\text{SDPA}}\|_2 + \epsilon}.
\]
Acceptable tolerances depend on dtype (BF16/FP16) and sequence length; values in the range $10^{-3}$–$10^{-2}$ are typical for long-sequence attention in low precision.

\paragraph{Datasets}
We use \textbf{synthetic} inputs ($q,k,v \sim \mathcal{N}(0,1)$) to avoid data-dependent branching and to stress uniform memory access patterns. Shapes sweep:
\[
(B,H,N,D) \in \{(1,1,N,64), (1,32,8192,D)\}, \quad N \in \{512,1024,2048,4096,8192\}, \ D \in \{32,64,128\}.
\]

\paragraph{Corner Cases}
\begin{itemize}
\item \textbf{Causal masking:} enabling the \texttt{--causal} flag increases control-flow divergence; both causal and non-causal paths are validated.
\item \textbf{Head dimension alignment:} some kernels prefer $D$ multiples of $8$ or $16$; misaligned $D$ may reduce tensor-core efficiency.
\item \textbf{Dropout and scaling:} tests use \texttt{dropout=0.0} and default scaling; adding dropout introduces RNG overhead.
\item \textbf{Dtype drift:} FP16 may show larger max-abs-diff than BF16; ensure no NaNs in guard value.
\end{itemize}

\subsection{Shared and Global Memory Usage}

Although we call library kernels (FA2/SDPA) rather than writing our own, we can reason about global memory traffic per forward pass ignoring caching effects:
\[
\text{Bytes}_{\text{in}} \approx (BHN D)_Q + (BHN D)_K + (BHN D)_V,
\]
\[
\text{Bytes}_{\text{out}} \approx BHN D.
\]
Thus, a lower bound on traffic is $4 \cdot BHND \cdot \text{sizeof(dtype)}$. For BF16/FP16, $\text{sizeof}=2$ bytes; for FP32 internal accumulation, registers and shared memory usage increase but do not directly contribute to HBM traffic.

\paragraph{Layout Effects}
\begin{itemize}
\item \textbf{FA2:} $qkv$ is constructed by stacking $q,k,v$ as views (\texttt{torch.stack}); this allocates a new packed buffer of size $3 \cdot BHND$, a one-time copy per run.
\item \textbf{SDPA:} \texttt{permute(...).contiguous()} materializes separate compact $q,k,v$ tensors, adding three copies of size $BHND$ before kernel launch.
\end{itemize}

\paragraph{Registers and Shared Memory}
\begin{itemize}
\item \textbf{FA2 kernels:} fuse attention pipeline ($QK^{\top}$, online softmax, $PV$) with high on-chip reuse (shared-memory tiles and register accumulators) to minimize HBM traffic.
\item \textbf{SDPA kernels:} use backend-selected fusion and tiling, with register/shared memory footprint depending on hardware and sequence length.
\end{itemize}

\section{PyTorch + Triton by Hongyang Cui}
\subsection{Implementation}

This implementation reproduces FlashAttention-2 in Triton with tile-wise streaming over the key/value sequence and an online softmax. We expose tiling knobs \texttt{BLOCK\_M}, \texttt{BLOCK\_N}, and \texttt{BLOCK\_D} and choose conservative defaults $128\times128\times64$ that fit head dimensions $D\le 128$ while controlling register pressure.

\paragraph{Kernel layout and grid}
We launch a 2-D grid with $\texttt{program\_id}(0)=b\cdot h$ and $\texttt{program\_id}(1)=\lceil N/\texttt{BLOCK\_M}\rceil$. Each program instance computes a $\texttt{BLOCK\_M}\times D$ output tile for one $(b,h)$. Inside a tile we iterate the key/value axis in blocks of size \texttt{BLOCK\_N}.

\paragraph{Forward pass (online softmax)}
Given $q\in\mathbb{R}^{M\times D}$, we stream $k,v$ tiles of shape $N\times D$ and maintain per-row running max $m_i$ and normalization $l_i$:
\[
m_{ij}=\max\!\bigl(m_i, \max\nolimits_{\text{row}}(qk)\bigr),\quad
p=\exp(qk-m_{ij}),\quad
l_{ij}=l_i\cdot e^{\,m_i-m_{ij}}+\sum p,
\]
\[
\alpha=\frac{l_i\cdot e^{\,m_i-m_{ij}}}{l_{ij}},\quad
\beta=\frac{1}{l_{ij}},\quad
\mathrm{acc}\leftarrow \alpha\cdot \mathrm{acc}+\beta\cdot (p\,v).
\]
A causal mask (if enabled) sets logits above the diagonal to $-\infty$ tile-wise. Inputs $Q,K,V$ are \texttt{fp16}; logits/probabilities/output accumulate in \texttt{fp32}. We use \texttt{num\_warps=4}; forward uses \texttt{num\_stages=2} (double-buffering K/V), backward uses \texttt{num\_stages=1}.



\paragraph{Precision and numerics}
Logits, softmax, and output accumulation are in \texttt{fp32}. Masked logits are $-\infty$ before exponentiation; online subtraction by $m_{ij}$ prevents overflow.

\subsection{Validation}
\label{sec:validation}

\paragraph{Correctness vs.\ SDPA}
We compare forward outputs to SDPA with identical $\mathrm{scale}=1/\sqrt{D}$ and the same causal setting, reporting $\max\lvert O_{\mathrm{ours}}-O_{\mathrm{sdpa}}\rvert$ typically in the $10^{-3}$ range for $(B,H,N,D)=(1,32,8192,128)$, due to \texttt{fp16} I/O and reduction orders.

\paragraph{Datasets / regimes}
We test random \texttt{fp16} tensors over $(1,1,512,64)$, $(1,1,1024,64)$, $(1,1,2048,64)$, $(1,1,4096,64)$, $(1,1,8192,64)$ and multi-head $(1,32,8192,\{32,64,128\})$.

\paragraph{Corner cases}
\begin{itemize}
  \item Head dim constraints: $D\le 128$ and $D\bmod 16=0$; \texttt{BLOCK\_D}$\mid D$.
  \item Boundary tiles masked on loads/stores and for causal comparisons.
  \item Warmup iterations to hide one-time costs in timing.
\end{itemize}

\subsection{Depth Complexity}

Let $T_r=\lceil N/B_r\rceil$ and $T_c=\lceil N/B_c\rceil$, with $B_r=\texttt{BLOCK\_M}$ and $B_c=\texttt{BLOCK\_N}$. Each program instance (a query tile) must iterate sequentially across all $T_c$ K/V tiles, with near-constant in-tile reduction depth. Thus
\[
D_{\mathrm{FA2}}=\mathcal{O}(T_c)\approx \mathcal{O}(N/B_c)=\mathcal{O}(N),
\]
reflecting the streaming design (contrast with $\mathcal{O}(N^2)$ work of naive attention).

\subsection{Shared Memory Access}
\label{sec:mem-acc}

This Triton kernel avoids explicit shared memory; tiles are loaded into registers, with software pipelining via \texttt{num\_stages}. Main register-resident arrays per program:
\begin{itemize}
  \item $\mathbf{q}$: $\texttt{BLOCK\_M}\times \texttt{BLOCK\_D}$ in \texttt{fp16}, loaded once per output tile.
  \item $\mathrm{acc}$: $\texttt{BLOCK\_M}\times \texttt{BLOCK\_D}$ in \texttt{fp32}.
  \item $m_i, l_i$: vectors of length $\texttt{BLOCK\_M}$ in \texttt{fp32}.
  \item Per K/V iteration: $\mathbf{k},\mathbf{v}$ of size $\texttt{BLOCK\_N}\times \texttt{BLOCK\_D}$ (load--use--discard).
\end{itemize}
Global-memory traffic per output tile (forward), with $M=\texttt{BLOCK\_M}$, $N=\texttt{BLOCK\_N}$, $D=\texttt{BLOCK\_D}$:
\[
\text{Loads: }Q: M D\cdot 2;\quad K: N_{\mathrm{ctx}} D\cdot 2;\quad V: N_{\mathrm{ctx}} D\cdot 2.
\]
\[
\text{Stores: }O: M D\cdot 2;\quad M,L: M\cdot 4 + M\cdot 4.
\]
(Units are bytes; \texttt{fp16}$=2$, \texttt{fp32}$=4$.)

\subsubsection{Sensitivity to Parameters and Optimizations}
\label{sec:params}

\paragraph{Tile sizes \texttt{BLOCK\_M}, \texttt{BLOCK\_N}}
Larger \texttt{BLOCK\_N} reduces the number of K/V iterations $\propto N/\texttt{BLOCK\_N}$ and the online-softmax update frequency, but increases per-iteration tile footprint. Larger \texttt{BLOCK\_M} amortizes $K,V$ loads across more queries but enlarges $\mathrm{acc}$ and stats $(m_i,l_i)$, potentially lowering occupancy.

\paragraph{\texttt{BLOCK\_D} (per-thread sequential work)}
Increasing \texttt{BLOCK\_D} improves math/byte ratio and reduces loop overhead but raises register usage for $\mathbf{q}$ and $\mathrm{acc}$. In practice, $64$ or $128$ are robust for $D\in\{64,128\}$.

\paragraph{\texttt{num\_warps} / \texttt{num\_stages}}
\texttt{num\_warps}$=4$ balances ILP and occupancy. Forward with \texttt{num\_stages}$=2$ overlaps global-memory latency with compute (double-buffering). Backward uses \texttt{num\_stages}$=1$ to ease register pressure alongside atomics.

\paragraph{Baselines}
Naive attention is memory-bound and materializes $N\times N$ scores. Our streaming FA2 avoids quadratic memory traffic. SDPA parity confirms numerical correctness; performance differences stem from differing fusion/tiling choices.

\subsubsection{Idealized Bandwidth/Compute Considerations}

Per $(b,h)$, forward loads $Q$ once, streams all $K,V$ tiles, and stores $O$ and $(M,L)$. Arithmetic intensity improves with $N$ since the same $Q$ participates in many $qk$ and $pv$ operations while per-tile overheads are constant. The remaining gap to peak (especially end-to-end) comes from (i) softmax reductions and exponentials, (ii) atomic stores to $dK,dV$, (iii) register-pressure limits on occupancy, and (iv) masking/control flow at ragged edges.
